## 2. Реалната цена при този стек

`FISHTAXI/index.html` = **154 KB ≈ 45 000 токена**.

Едно пълно пренаписване на файла от Fable:

```
45 000 × $50 / 1 000 000 = $2.25
```

40 итерации при дебъг сесия = **~$90 само от изхода**.
Точно така изгоряха първите $100 кредит.

**Изводът:** скъпото не е моделът, а **връщането на цял монолитен файл при всяка поправка.**
Изходните токени са 5x по-скъпи от входните.

## 3. Маршрутизация

### Ниво 0 — без модел

Преди да отвориш чат:

- счупен скрейп → `curl` към източника + diff срещу вчерашния HTML
- червен билд → лог от GitHub Actions
- JS не тръгва → `node --check`
- worker не отговаря → `curl` към endpoint-а

Класическите виновници тук са познати: промяна на селектор, cp1251 charset,
`dd.mm` парсване, изтекъл токен, кеш на raw CDN (~5 мин).

### Haiku 4.5
Преводи (BGR, 14 езика), преформатиране на JSON, координати на зони,
regex, commit съобщения, README.

### Sonnet 5 — работният кон
Рутинни промени по съществуващи файлове, CSS/UI, нов скрейпър по познат
шаблон, GitHub Actions YAML, Kotlin boilerplate, тестове.

### Opus 5 — тук отива 90% от бившата Fable работа
Сложен дебъг, многофайлов рефактор, архитектурно ревю, worker логика,
`window.__applyLive` мостове, KV/токен схеми.

> Fable е 2x над Opus по API цена, но за Pro съотношението е безкрайно:
> **Opus е безплатен, Fable не е.**

### Fable 5 — само проектиране, никога поправяне
Единственият валиден случай: **нова архитектура от нула**, където грешен
избор струва дни. Пример: първоначалният дизайн на такси приложението.

Забранено за Fable: дебъг, преводи, boilerplate, изследване „защо не работи",
пренаписване на файлове.

## 4. Протокол за Fable сесия

1. Подготви брифа в **Opus** (безплатно) — контекст, ограничения, желан изход.
2. Отвори **нов, кратък чат**. Не продължавай стар — дългият контекст се
   препрочита на всеки ход.
3. Поискай изрично: **патч или само променената функция, не цял файл.**
4. Вземи резултата и **затвори сесията.** Итерациите правѝ в Opus.

---

## 5. Структурни мерки

1. **Никога цял файл.** Ползвай съществуващия модел „файлове >25 KB се пачват
   през Python скрипт в GitHub Actions". Същият подход спестява ~10x пари.
2. **Разбий монолита.** Модули + билд стъпка, която ги слепва в single-file.
   Offline-first изходът се запазва, редакцията пипа 3k вместо 45k токена.
3. **Нов чат за всяка задача.**
4. **Таван на разхода** в Settings → Usage → Adjust limit. Дръж го нисък.

## 6. Кога Max планът има смисъл

На Max Fable е включен до 50% от седмичния лимит.
Правилото: **ако разходът за Fable кредити надхвърля цената на Max месечно,
Max е по-добър** — фиксирана цена вместо метър.

Но първо приложи т. 3–5. Има голям шанс да не потрябва.

## 7. Инструкция за Claude (за User Preferences / Project instructions)

> Преди да започнеш задача, кажи ми кой модел е правилният за нея:
> Haiku (преводи, данни, regex), Sonnet (рутинен код по съществуващи файлове),
> Opus (дебъг, многофайлов рефактор, архитектурно ревю), Fable (само нова
> архитектура от нула). Ако съм във Fable за нещо, което Opus може — кажи ми
> да сменя, преди да пишеш код. Никога не връщай цял файл; давай само
> променената функция или патч. При счупен скрейп първо ме питай проверил ли
> съм източника ръчно.
